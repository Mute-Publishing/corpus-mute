# Mute Wikibase deployment

Wikibase Suite (WBS) for the Mute corpus catalogue. Same method as `cps-deploy-1`
(vendored `wikibase-suite` submodule, compose override files, Traefik with one
path-routed domain), with one difference: here Traefik terminates TLS itself with
Let's Encrypt, because there is no external proxy in front of the Hetzner server.

| | Local | Production |
|---|---|---|
| Compose project | `mute-wikibase-local` | `mute-wikibase-prod` |
| URL | http://localhost:8091/ | https://corpus.metamute.org/ |
| Override file | `docker-compose.override.local.yml` | `docker-compose.override.prod.yml` |
| Location | this folder | `/opt/mute-wikibase` on `178.105.222.174` |
| WBS version | `wikibase-suite` @ `b4208963` (WBS 8.0.1), image `wikibase/wikibase:8.2.1` | same |

Routes (single domain): `/` Wikibase, `/query/` Query UI, `/query/proxy/sparql` SPARQL,
`/tools/quickstatements/` QuickStatements. See `config/traefik-dynamic.yml`.

## Secrets

- Production `.env` lives only at `/opt/mute-wikibase/wikibase-suite/.env` (mode 600), generated on the server by
  `scripts/server-env.sh`. The admin password was never printed or sent anywhere. Read it yourself:
  `ssh root@178.105.222.174 "grep -E '^MW_ADMIN_(NAME|PASS)=' /opt/mute-wikibase/wikibase-suite/.env"`
  and store it in your password manager.
- Local `.env` is generated by `scripts/new-local-env.ps1` (random, gitignored).
- Never commit `.env`, `bootstrap.*.json` or backups (see `.gitignore`).

## Local

```powershell
Set-Location wikibase-deploy
git submodule update --init
.\scripts\new-local-env.ps1
docker compose -f wikibase-suite/docker-compose.yml -f docker-compose.override.local.yml --project-directory wikibase-suite up -d
```

Never add `-v` to `down` unless you intend to delete the data.

## Production operations

Scripts in `scripts/` are copied to `/opt/mute-wikibase/scripts/`. From Windows use the wrappers (plain `ssh` in the
VS Code terminal tool can hang; these use timeouts and file-redirected output):

```powershell
.\scripts\push.ps1   -Local .\scripts\backup.sh -Remote /opt/mute-wikibase/scripts/backup.sh
.\scripts\remote.ps1 -Command "bash /opt/mute-wikibase/scripts/server-verify.sh" -TimeoutSec 90
```

| Script | Purpose |
|---|---|
| `preflight.sh` | read-only server inventory |
| `server-wipe.sh` | DESTRUCTIVE: removes the previous deployment (needs `--yes`); already run once |
| `server-env.sh` | create production `.env` with random passwords generated on the server |
| `server-up.sh` | `docker compose up -d` (never `down -v`) |
| `server-verify.sh` | containers, HTTPS endpoints, certificate, memory |
| `server-load.sh` | run `etl/upload_to_wikibase.py` on the server (`bootstrap` or `import`) |
| `server-count.sh` | SPARQL counts + idempotency re-run |
| `server-check-item.sh` | print one item's statements |
| `load-wiki-pages.sh` | load `config/sparql-examples.wiki` as `Project:SPARQL/examples` (the Query UI Examples dialog) |
| `server-query-test.sh` | run every query in the examples file against the live endpoint and print row counts |
| `server-check-examples.sh` | check the examples page is served and see how the Query UI finds it |
| `backup.sh` | DB dump + volumes + config, 7 sets retained |
| `server-harden.sh` | fail2ban, unattended-upgrades, nightly backup cron |

Redeploy after changing a compose or Traefik file: push the file, then `server-up.sh`.

### Data load

1. `python mute-er-model/etl/csv_to_xml.py` then validate (`mute-er-model/etl/validate_xml.py`, run in a python 3.12 container: needs lxml).
2. Push `xml/mute-issues.xml` and `etl/upload_to_wikibase.py` to `/opt/mute-wikibase/{xml,etl}/`.
3. `server-load.sh bootstrap` once (writes `output/bootstrap.prod.json` with the created IDs), then `server-load.sh import`.
   Import skips issues whose `Mute issue ID` (P2) already exists, so it is safe to re-run.

## Known issues / decisions

- Traefik needs `--entrypoints.websecure.http.tls.domains[0].main` because the routing file has no `Host()` rule;
  without it Traefik serves its default self-signed certificate. This is in the prod override.
- SSH still allows password authentication (distro default, `PermitRootLogin prohibit-password`). Consider turning
  password login off once a second key is in place (the CPS baseline is key-only).
- Local Docker Desktop engine was returning HTTP 500 during this work, so the local-first test run did not happen;
  the first end-to-end test of the uploader was a 1-issue import on the server.
